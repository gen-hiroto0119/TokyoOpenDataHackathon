# あつまっぷ

新宿駅で、別々の路線から来る人たちの**集合場所と構内の経路**を出すモバイル Web です。責務は駅の中と出口までで、その先の徒歩は Google Maps へ渡します。

**動くもの: https://atsumap.h-furugen-24-7-1533.workers.dev**

東京都オープンデータ・ハッカソンへの提出物です。最初の対象は新宿駅西側、目的地は東京都庁を想定しています。

## 解く問題

巨大駅では「新宿駅で待ち合わせ」だけでは足りません。別の鉄道会社・路線・階から来る人は、同じ出口名を別の場所として理解したり、階や通路を誤ったりします。最短距離だけで集合地点を選ぶと、一人だけが複雑な通路を歩かされます。

あつまっぷは、各自の到着路線と集合後の目的地から、**全員の負担が偏らず、名前で説明でき、集合後すぐ地上に出られる**地点を選びます。

## 触ってみる

2 台（またはブラウザの 2 タブ）で試せます。

1. 公開 URL を開き、名前と行き先（東京都庁など）を入れてルームを作る
2. 出てきた招待リンクを別の端末で開き、名前を入れて参加する
3. 各自が到着路線を選ぶ（JR / 京王 / 丸ノ内）
4. 2 人以上そろうと集合候補が出る。ホストが「この地点にする」を押す
5. 各自の画面に自分の経路が出る。下が今の手順で、上へスクロールして進む
6. 迷ったら「いまいる場所」から経路上の地点を選ぶと、そこから計算し直す
7. 出口まで着いたら「地図アプリで道順を見る」で Google Maps に渡す

参加者の増減や到着申告は、WebSocket の通知で相手の画面にすぐ出ます。

## 決めていること

- **アカウントを作りません。** 参加は招待リンクと名前だけです。
- **位置を測りません。** 駅の中では現在地を出せないので、利用者が確認しながら進みます。進み具合を決めるのはスクロール位置です。
- **改札は選ばせません。** 路線を入れると、その路線の改札すべてを始点にした探索で、一番近いものをこちらが選びます。
- **AI に決めさせません。** 順位は国交省の屋内地図から作ったグラフ上の探索と、下に書いた条件の順だけで決まります。学習した重みも合成スコアもありません。同じ入力なら必ず同じ答えが出ます。
- **集合場所はホストが決めます。** 候補は人が増えるたびに作り直しますが、決めた地点は動かしません。向かっている途中で行き先が動くと迷うためです。
- **看板の文字をそのまま出します。** 出口の番号は事業者ごとに振り直されていて、新宿駅に「7番出入口」は 3 つあります。それでも経路を出して連れて行く以上、目の前の看板と一致していることの方が大事です。
- **間違っていることを前提にします。** 店名は 2020 年調査時点のものです。店舗や出入口は現状と違うことがあります。断定して書かず、現地の表示を送れる導線を置いています。

## どう選んでいるか

集合候補は **72 件**（改札・タクシー・店・バスタ前・手書きの大きな口）。この順で並べます。合成しません。

1. 全員が到達でき、指定されたバリアフリー条件を満たす
2. **一番長い人**の移動距離が最小
3. 同点なら全員の合計が最小
4. さらに同点なら、集合場所から出口までが短い
5. 最後に説明しやすさ（交番 5 > 案内所 4 > バスタ前・地上の大きな口 3 > 改札 2 > 店舗 1）

出口は「集合場所からの徒歩 ＋ 出口から目的地までの直線 × 1.35 ＋ 看板が無ければ 60m」が最小のものを選びます。1.35 は市街地の迂回率で、これが無いと駅の反対側の目的地に対して「早く外に出た方が得」に倒れます。

代表ケース（JR・京王・丸ノ内の 3 人 → 東京都庁）では、1 位が **スターバックス コーヒー 新宿西口店（B1F）**、一番長い人で 105.5m、合計 266.6m、出口 9 から地上へ（157.9m）、という答えが出ます。

## 使っているデータ

国土交通省「新宿駅周辺屋内地図」（令和2年度更新版、政府標準利用規約第2.0版 / CC BY 4.0 互換）。取得日と SHA-256 は [`data/manifests/mlit-indoor-shinjuku-r2.json`](data/manifests/mlit-indoor-shinjuku-r2.json) に残しています。東京都の店名は使いません。

取り込んだ結果:

| | |
|---|---|
| 歩行グラフ | ノード 1,985 / リンク 5,012（方向展開後）/ 総延長 63.2km |
| 改札 | 37（JR 14・京王 9・丸ノ内 7・小田急 3・大江戸 3・都営新宿 4・西武新宿 1） |
| 集合候補 | 72（改札 25・タクシー 2・店 43・バスタ前 1・手書きの大きな口 1） |
| 出口 | 109（看板の文字があるもの 90） |
| 近くの設備 | エレベーターが 50m 以内 23 件 / トイレが 50m 以内 20 件 |

取り込みは [`apps/worker/scripts/ingest`](apps/worker/scripts/ingest)（TypeScript）。件数・連結性・出口・二回実行の一致など **13 項目を機械検査**してから出力します。

## 作り

```
apps/web     画面（React + StyleX + Vite、390 × 844）
apps/worker  API と配信（Hono + Cloudflare Workers + Durable Objects）
```

- 推薦はステートレス。ルーム 1 件が Durable Object 1 つで、状態だけ持ちます
- 本番は Worker が画面も配る 1 origin。招待リンクがそのまま開きます
- ルームの更新は WebSocket（Hibernation）で通知し、画面は取り直します。切れてもポーリングが正しさを保ちます
- 行き先の検索は Google Places をクライアントが呼びます。Worker は名前と緯度経度を受け取るだけで、キーが無くてもプリセットで動きます

## 開発

```bash
pnpm install
pnpm dev        # worker (:8787)
pnpm dev:web    # 別のターミナルで Vite (:5173) を開く
pnpm check      # typecheck と 190 件のテスト
pnpm run deploy # check → build → Cloudflare へ
```

グラフとカタログは [`apps/worker/data`](apps/worker/data) に同梱しています。作り直すときは、国交省の統合版を `data/raw/mlit` に展開して:

```bash
pnpm --filter worker ingest          # 検査を通してから生成
```

テストは固定の小さなグラフ（契約の凍結）と、実データのゴールデン・性質テスト（全 72 候補について経路の連続性・向き・距離の和を検査）に分かれています。

## できていないこと

- **構内の地図を出しません。** 元データのノード座標は地物の代表点で、通路の形を持ちません。試作した図は「地図に見えない」ため採用せず、手順の並びだけにしました。
- **乗換案内の読み取り（OCR）と案内板の撮影、いまいる場所の指定は未実装です。** 画面の導線ごと外しています。
- **ホームから改札までは案内できません。** 番線に対応するノードがデータに無いため、始点を改札にしています。
- **店名は 2020 年調査時点のものです。** 西口の再開発で現状と違う可能性があります。
