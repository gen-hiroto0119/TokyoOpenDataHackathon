出典と取得日は [`data/manifests/shinjuku-terminal.json`](../data/manifests/shinjuku-terminal.json)。

数えた日: 2026-08-17。取り込みは [`tools/ingest`](../tools/ingest)（出力は `apps/worker/data`。`data/graph/` は gitignore のまま）。

## 出口をどう拾ったか

**`marker=entrance` の地物が 96 件ある。全部 1F。** 出入口は地上に出る所なので、これは正しい。

最初は番号付きの 22 件しか拾えていなかった。`com-entity` の数字名だけを見ていたためで、**この層を見落としていた**。

### ラベルは番号・記号・空のいずれか

96 件のうち 54 件にラベルがあり、`1`〜`22`, `15B`, `A`〜`G`, `M`, `PL`, `R`, `RL`, `S` が出る。残り 42 件は空。

**番号は事業者ごとに振り直されている。** 「3」は 500m 離れて 3 箇所、「5」「7」「9」も 3 箇所ずつある。Apple のマップでも同じ状態で、番号のない出口やアルファベットの出口も現地に存在する。**データの誤りではなく、現実が一意でない。**

一度「一番近い改札から『西口』『東口』を取って修飾する」方式を実装したが破綻した。400〜500m 離れた改札を根拠にすると新宿三丁目駅の出口を「新宿駅東口」と呼んでしまい、修飾しても番号の衝突は残り、無名の出口が「西口 出入口」×13 になった。

**だから修飾しない。看板のとおりに出す。** 曖昧なのは口頭で場所を指すときの話で、この案内では違う。利用者はすでに集合していて、こちらが出した経路をたどって一緒に歩く。目の前の看板の「7」を見つければよく、どの事業者の 7 番かを知る必要がない。歩かせている限り、文脈はこちらが供給している。

### 24 件は経路データに結ばれていなかった

96 件のうち 24 件は、経路データがその地物を参照していない。ただし外にあるわけではなく、**全件が 2〜12m 以内に 1F のノードを持っていた**。結びつけが抜けているだけ。

同じ階の一番近いノードへ 15m 以内で寄せて、23 件を回収した（1 件は遠すぎて外した）。`新宿駅11`、`新宿駅16`、東南口、バスタ新宿前、西武新宿駅がここで戻った。

ただし回収した中には `西口地下広場`、`メトロプロムナード`、`東西自由通路` のような地下側の点も混じる。**看板の文字がない出口は、着いても合っているか確かめようがない。** だから推薦は看板のあるものを優先する（[`CORE.md`](./CORE.md) の持ち出しコスト、60m）。

### 階は混ざっていない。ただし「屋外」が無い

層は `zlevel` で定義されていて、`1F` は 0、地上。出口 92 件はすべて 1F のノードに紐づく。地下の点は入っていない。

```
B5F -7   B3F -5   B2F -3   M1F -1   2F  1   4F  3
B4F -6   MB2F -4  B1F -2   1F   0   3F  2
```

**`M1F` は zlevel -1 で地下。** B1F と 1F の間の中間層で、地上の中2階ではない。97 ノードある。画面に「M1F」と出すと地上と誤解されるので、表示は考える必要がある。

**11 層すべてが `type: indoor`。このデータには「屋外」という区分が無い。** だから「出口」とは外に出る場所ではなく、モデル化された空間が途切れる場所を指す。街路への扉と館内の扉が同じ `marker=entrance` になるのはこのため。

出口の 78 件は 1F の行き止まり（出次数 1）で、経路がそこで終わる。**通り抜けている 14 件は、外への出口ではなく館内の扉の可能性が高い。** 縦のつながりを持つのは 16 件だけで、残りは水平リンクのみ。地下街への階段は出口ノードそのものではなく別の場所にある。

### 何が出口なのかは、データからは決まらない

`marker=entrance` は街路への出口だけではない。地下広場への入口、エレベーターやエスカレーターの地上開口、歩道橋の階段も同じ印が付く。92 件のうち 18 件は階段（9）・エレベーター（5）・エスカレーター（4）のノードに紐づく。

現地と照らすと**これらは本物のアクセス経路**で、除くべきものではない。一方で、どれが「出口」でどれがそうでないかは、属性からは判別できない。**人が見て決めるしかない。**

そのため `data/labels/exits.json` を用意した。

```json
{ "1760710": { "labelJa": "京王百貨店口" },
  "1759884": { "exclude": true } }
```

`labelJa` は東京都のラベルを上書きし（`labelSource: "manual"` になる）、`exclude` はカタログから外す。空欄のものは触らない。

### 店やビルにつながる出入口は経路が繋がっていない

歩行網は駅のコンコースを対象にしていて、商業施設の中は引いていない。ルミネエスト、ルミネ１、ヤマダデンキ、新宿区役所第一分庁舎につながる出入口は、面はあってもノードが繋がっていなかった（近さで寄せて回収した 23 件に含まれる）。**寄せた先はコンコース側のノードなので、そこまでは案内できるが施設の中には入れない。**

### 拾えていないもの

**南口・新南口・甲州街道方面と、百貨店を通って外に出る経路は入っていない。** 東南口・Flags・バスタ側の 4 件はラベルが空で、寄せた先も地下側の点になる。

### OpenStreetMap と突き合わせた

Overpass で出入口ノードだけを引くと、この範囲に 208 件（名前あり 125 件）ある。逆ジオコーディングと違い店名が混ざらない。うちの 92 件のうち 55 件が 15m 以内で対応した。

| | 件数 |
|---|---|
| 番号まで一致 | 30 |
| 番号がずれる | 14 |
| 空欄を埋められる | 11 |
| 近くに OSM のノードが無い | 37 |

**東側（新宿サブナード）はほぼ完全に一致する。** サブナード 2〜16, 21, 22 が揃って合う。ずれは西口地下に集中していて、いずれも 1〜2 番のずれ。

```
都データ 18 → OSM 新宿駅17      都データ 12 → OSM 新宿駅11
都データ  5 → OSM 新宿6         都データ  9 → OSM 新宿駅8
都データ 20 → OSM サブナード18    都データ 19 → OSM サブナード17
```

OSM も現地とは限らない。どちらが正しいかは現地で決める。採用する場合は ODbL の表示義務が戻る。

外した 24 件には歩道橋 7、階段 3、判断できないもの 2、閉鎖中の出口 1 が含まれる。**閉鎖中の出口は経路の終点にしない。** 案内しても現地で通れない。**このデータは駅の構内図ではなく「新宿駅まわりの歩行空間」なので、歩道橋やデッキも入る。** 2F の地物 276 件が経度 139.6968〜139.7019 に広がるのも同じ理由。間違いではないが、待ち合わせの出口としては使えない。

カタログの各出口は `evidence` を持つ。`checked` は人が見たもの、`hypothesis` は取り込んだだけ。

## 何が入っていないか

### 網は駅で終わる

**西端は経度 139.6966 で、都庁（139.6917）の 442m 手前。** 出口から目的地までは計算できない。

だから**地上ぶんは直線距離に迂回率 1.35 を掛けた見積もりで扱い、実際の経路は Google Maps に渡す。** 都庁のように地下道で直結している行き先もあるが、そこは Maps の方が詳しい。

### ホームから改札まで計算できない

歩行網のノードは通路・階段・EV・改札まわりが主。JR・小田急の番線名はあるが、対応ジオメトリにナビノードが付いていない。京王・丸ノ内のホーム名は見当たらない。**改札より内側は計算できない。**

### 営業時間はほぼ無い

時間帯を持つ地物は 15,556 件中 **12 件**。契約は `asOf` で時間帯を絞れるが、実データではほとんど効かない。

### 名前が入っていないもの

[`RESEARCH.md`](./RESEARCH.md) のとおり、西武新宿、バスタ新宿、都営新宿線、都庁はエンティティ名に出てこない。

### 行き止まりノードは出口ではない

742 件ある行き止まりの中身は設備で、階段 57、エレベーター 27、ATM 22、コインロッカー 20、エスカレーター 19、トイレ 24。網が設備ごとに枝を伸ばしているだけ。ここを出口候補にすると全部間違える。

## 取り込みで直したこと

**map の反復順に依存していた。** Go の `range` は順序が決まらないので、同じノードに複数の地物が寄ると残る方が実行ごとに変わり、出口が 92 件で看板ありが 52 件だったり 54 件だったりした。ID 順に固定した。3 回続けて同じハッシュになることを確認している。

**ノードを ID の若い順で選んでいた。** 一つの地物に複数のノードが付くことがある。若い順に取ると出入口の中心から最大 13m ずれた。一番近いものを選ぶようにして、平均 1.9m になった。

**同じノードに寄った出入口のうち、看板のある方を捨てることがあった。** 現地に表示があるのに無名として出てしまうので、ラベルのある方を残すようにした。

## 残っている課題

- **1 位と 2 位の差が小さい。** 代表ケースで 180m と 187m。同点の幅を持たせていないので、データが少し変われば順位が入れ替わる。
- **分岐の数が粗い。** 次数 3 以上を全部数えているので 9〜27 になる。人が迷う分岐だけを数える基準が要る。
- **屋外の歩行データを足す余地がある。** [新宿駅西部の歩行空間ネットワーク](https://catalog.data.metro.tokyo.lg.jp/dataset/t000029d0000000007)（デジタルサービス局、2020年10月、更新予定なし）は西口から都庁方面の屋外を含む。別系統なので繋ぎ目を手で作る必要がある。繋げば地上ぶんを直線ではなく経路で出せる。
