# 画面と部品

方針の正本は [`PRODUCT.md`](./PRODUCT.md)、応答フィールドの正本は [`./RECOMMENDER.md`](./RECOMMENDER.md)、部品と文言の正本は Figma。この文書は**決めたことと、その理由**だけを書く。

Figma の `Concept Display` は探索用。何を作るかだけを引き継ぎ、見た目・情報設計・地名や路線の例は引き継がない。

## 決めたこと

### 参加の仕組み

**アカウントを作らない。** サインインもパスワードも無い。

**招待リンクだけで参加する。** リンク自体が秘密。合言葉は置かない。リンクと同じ経路で合言葉を渡すなら何も守らないし、8 桁の英数字は混雑した構内で片手では打てない。忘れたときに再発行する手段も無い。

**名前は参加時に入れる。** ホストは画面1、参加者は画面2。`Participant` も `Arrival` も名前を出す前提だが、入力する場所がどこにも無かった。名前が他の参加者に見えることは入力欄の下に書く。

### 行き先

**Places で検索して選ぶ。** 新宿駅の中でどこへ行くかを選べるようにする。目的地は名前と緯度経度を持つ。

**Places を呼ぶのはクライアント。** 推薦 Worker は名前と緯度経度を受け取るだけなので、契約は入力手段に依存しない。キーが失効したときのためにプリセットをフォールバックに残す。

**写真は任意。** Places の写真は別課金で、帰属表示が必須、保存できない。写真が無い場所もあるので、無いときの形を持つ。

### 到着情報

**登録された路線から選ぶ。** 計算が受け取れるのはカタログの路線だけなので、書いて特定させない。乗換案内の画面から読み取ると、同じ欄に入る。

**読み取った結果は正本にしない。** `Field / Select` に出して利用者が確認して確定する。読み取りが外しても、一覧から選び直せる。

**入力するのは路線だけ。** 改札は選ばせない。到着方面も要らない（下記）。

### 改札

**利用者に選ばせず、こちらで選ぶ。** 利用者は改札名を知らないし、何号車に乗っていたかはこちらから分からない。そして改札は目的ではなく計算の途中でしかない。

入力は路線にして、その路線の改札すべてを始点にした多点始点最短で距離を出す。行くのが大変な改札は自然に選ばれない。選ばれた改札は経路の最初の手順として出す。現地で違っていたら `confirmed` で直せる。

ホームや番線から改札までは計算できない。`RESEARCH.md` のとおり、番線に対応するナビノードが無い。当てにいかず、選び直せるようにする。

### 集合場所の計算

**イベントごとに再計算する。** 参加者が入る、到着情報が変わる、地点を確認する、そのたびに候補を作り直す。だから「集合場所を計算する」ボタンは置かない。

**選べるのはホストだけ。** 「この地点にする」を押した時点でルームが確定する。別に確定ボタンは作らない。参加者も同じ候補を見られるが、ボタンは出さない（`Candidate` の `Action=Hidden`）。なぜその地点なのかが分からないと、公平性を出す意味がなくなる。

**確定した集合場所は再計算で変えない。** 順位が入れ替わっても、決めた地点はそのまま残す。向かっている途中で行き先が動くと迷う。

### 経路案内

**1 手順 1 画面をスクロールで送る。** 今の手順が手順エリアの中央にスナップする。前後の端は見える。送るのはスクロールだけで、JavaScript の送り操作は置かない。スクロール位置が現在地。測位しないので、どこまで進んだかを決めるのは利用者。

**下に手順 280、残りは地図。** 390 × 844 から App bar 52 と Tab bar 56 を引いた 736px のうち、手順は今の行が中央に来る高さ。地図の図は 280 のまま中央に置く。

**地図の点はスクロール位置に打つ。** GPS ではなく、利用者が今いると思っている手順のノードに置く。**青にしない。** 青い丸は GPS の慣習色で、測位していると誤解される。`presence/self` を使う。

**手順の行は 2 種類ある。** 名前のあるノードは目印が主役、名前のない通路は距離が主役。都のナビ網は無名ノードが大半なので、地点に動きを書く形だと通路が表せない。

**距離を主役にしない（地点の行では）。** 測位しないと「あと 40m」が減らない。地下通路で距離を数えて歩く人はいない。

**番号と「次」は付けない。** 順序は並びで分かる。進み具合は文字の濃さと大きさで示す。

### 出口への引き継ぎ

`Handoff` を画面6の経路の末尾に置く。出口に着く前は Waiting、着いたら Ready。**専用画面にはしない。** `Handoff` に Waiting があるということは、着く前から置けるということ。専用画面にすると、着いた瞬間に画面が切り替わったことを利用者に意識させる。

**出口の名前は看板の文字をそのまま出す。** `onward.exit.label` が `7` なら「出口 7」と書く。「西口 7番出入口」のように言い換えない。番号は事業者ごとに振り直されていて新宿駅に「7番」は 3 つあるが、経路を出して連れて行っている以上、目の前の看板と一致していることの方が大事。

**ラベルが空の出口がある。** そのときは「地上出口」と出す。空欄や記号を出さない。詳しくは [`DATA.md`](./DATA.md)。

**間違っていることを前提にする。** 出口の名前は 96 件を人が見て決めたが、現地の表示は変わるし、見落としもある。`onward.exit.evidence` が `hypothesis` のものは断定して書かない。そして**どの出口にも「表示が違う」導線を置く。** `Handoff` の中に小さく置き、押すと現地の表示を書ける。直った内容は `data/labels/exits.json` に戻す。

正しさを作り込むより、間違いを直せる形にする方が、この規模のデータでは早い。

## 採らなかったこと

| 案 | 理由 |
|---|---|
| ARナビゲーション（路面3D矢印） | `RESEARCH.md`：Visual SLAM / ARCore は PWA 対象外。3D 構内表示は MVP 後。同じ手順の並びを使うので、後から表示方法として足せる |
| サインイン | MVP に認証要件が無い |
| 合言葉・パスワード | リンクと同じ経路で渡すなら守らない。駅で打てない。再発行できない |
| 到着方面の入力 | 改札を路線から選ぶので、計算に効かない |
| 行きやすさ指数 | `PRODUCT.md` が合成点を禁じている。同じ情報を階移動・分岐の内訳で出せば説明できるまま |
| ホイール（ドラムピッカー） | 中央固定・慣性・スナップの選択部品。行き過ぎるうえ読み上げと拡大に弱い |
| 前後の手順をぼかす・傾ける | 迷ったときに前の手順を読み返せることが中心価値。屋外光と歩行中の条件でも不利。Foundations にトークンも無い |
| 地図に参加者マーカー | 経路リストの集合場所バッジの方が「今どこを目指しているか」が分かる |
| 高速道路の標識の見た目 | 情報の並べ方は借りるが、緑地に白は「高速道路の案内」という意味を既に持つ |
| コンビニ・座れる場所のアイコン | 都データの `facility` に無い。出すと根拠のない情報になる |
| Routes API / Places の Worker 呼び出し | 出口は徒歩距離と直線の見積もりで選べる。Worker は座標を受け取るだけ |
| グループ一覧、オンボーディング 3 枚 | 縦切りに含まれない |

### 作らないと決めたもの

**Dialog。** いまの 8 画面に、割り込んで確認を取る場面が無い。ルームは 24 時間で消えるので削除操作も無く、カメラの許可は `Permission / Camera` が使う場面で聞く。必要になったら作る。

**`status/success` と `status/attention` の色。** 状態は言葉と形で示し、色に依存させないと決めた。色を使う例外は `problem`（経路外）だけで、そこは急を要するから。`status/attention` が `status/progress` と同値なのは欠陥ではなく、この決定の結果。

**`map/marker/arrival` と `map/marker/handoff` の色の違い。** どちらも白のままで、形（輪とひし形）で分ける。同じ理由。

**Field の日時型。** ルーム有効期限は `Field / Text` に整形済みの文字列を出すだけで足りる。日時の選択は端末の標準の部品が受け持つ。

**`Invite / Consent`。** 参加の同意はボタンを押すことで、必ずオンにしないと進めないトグルは選択に見せかけた通過儀礼だった。画面 2 から外し、部品も削除した。

## 組んで分かったこと

- **順位のフィールドは要らない。** 並び順が順位。バッジを足すと `ui-copy.mdc` の自己評価に寄る
- **画面の見出しは App bar が持つ。** 本文側に見出しを置くと二重になる
- **App bar は高さを固定する。** 戻るを隠すと中身が文字だけになり 32px に縮んだ
- **枠線を外側に置く部品は、余白ゼロの枠に入れると切れる。** Button で 3 回起きた
- **階移動と分岐は人ごとの値。** 改札から集合地点までで、全員を 1 つの数字にまとめられない。集合地点から出口までとも区間が違う
- **設備アイコンは写真より使える。** 写真は撮った分しか出せないが、`facility` は全候補に出せる
- **オンボーディングは動かす。** 3 人が改札から中央へ集まり、集合場所が現れ、その先が点線で伸びる。文字を読む前に何をするアプリか分かる。Figma のプロトタイプで、開始フレームから 0.4 秒後にスマートアニメート、1.8 秒後にディゾルブで戻してループする
